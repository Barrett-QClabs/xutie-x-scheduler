# 序帖使用教程

这份说明给第一次从 GitHub 拿序帖的人。仓库地址：

https://github.com/Barrett-QClabs/xutie-x-scheduler

序帖是装在你自己电脑上的定时发帖程序。它用你自己的 X（Twitter）开发者凭据，按你设的时间把队列里的文字发出去。程序里没有共享密钥，也没有给别人用的账号。

下载下来的是源码，不是已经装好的软件。还要在你的电脑上构建并启动。窗口或容器关了，到点的帖子就不会发出去。

下面的步骤只根据仓库里的说明、配置模板和界面文字。费用以 X 自己的控制台为准。这里不保证不封号，也不保证免费。用自己的账号做第一次试验，后果由你自己承担。

## 1. 从 GitHub 拿到文件

这个仓库是公开的。打开上面的网页、下载 ZIP、用下面的地址 `git clone`，都不需要先注册 GitHub 账号。账号只在你要登录、收藏、提问题或提交修改时才需要。

两种拿法，选一种：

**下载 ZIP**

1. 打开仓库页面。
2. 点绿色的 **Code**，再点 **Download ZIP**。
3. 解压。文件夹名一般是 `xutie-x-scheduler-main`。后面的命令都在这个文件夹里执行。

**git clone**

已经安装 Git 时，在终端执行：

```bash
git clone https://github.com/Barrett-QClabs/xutie-x-scheduler.git
cd xutie-x-scheduler
```

## 2. 开始之前要有什么

推荐用 Docker，并且要用带 Compose v2 的版本（命令是 `docker compose`，中间没有横线）。仓库没有写死 Docker 的小版本号。

不用 Docker 时，安装 Node.js 22。镜像和仓库的检查都按 22 来。Node 自带 npm。

另外准备：

- 一个浏览器。
- 至少 16 位的随机字符串，用来加密你稍后保存的凭据。可以用 `openssl rand -base64 32` 生成。不要把这个字符串发给别人。
- 只想先看界面时，先不要去申请 X 的密钥。默认就是模拟，不会请求 X。

## 3. 用 Docker 启动（推荐）

在解压或 clone 出来的文件夹里：

```bash
cp .env.example .env
```

用文本编辑器打开 `.env`。至少把 `CREDENTIALS_ENCRYPTION_KEY=replace_me` 换成你的长随机字符串。其余先保持模板里的样子：

| 字段 | 模板里的值 | 作用 |
| --- | --- | --- |
| `CREDENTIALS_ENCRYPTION_KEY` | `replace_me`（必须改掉） | 加密数据库里的凭据。换掉之后，旧凭据解不开，要重新填写 |
| `DATABASE_PATH` | `./data/xqueue.sqlite` | 本机直接运行时的数据库。用下面的 Compose 时，数据改存在卷里 |
| `X_API_MODE` | `mock` | 只有精确写成 `live` 才会请求 X。别的值都是模拟 |
| `HOST` | `127.0.0.1` | 本机直接运行时只听这台电脑。Compose 会在容器内改成 `0.0.0.0`，但端口只发布到本机 |
| `PORT` | `3847` | 页面端口 |
| `XUTIE_AUTOMATION_SUPERVISOR` | `off` | 不要改成 `on`。那会去拉起另一套旧的关注进程 |
| `XUTIE_ACCOUNT1_FOLLOW` 等四项 | `off` | 自动关注、自动取关。第一次使用保持关闭 |

然后：

```bash
docker compose up -d --build
```

第一次会下载基础镜像并构建，需要网络，可能要几分钟。成功后这个容器会在后台一直跑，电脑重启策略是 `unless-stopped`（Docker 自己还在运行时会把它拉起来）。

浏览器打开：

http://127.0.0.1:3847

不要把这个端口暴露到公网。序帖没有登录，谁能打开页面，谁就能改队列。

看它是否在跑：

```bash
docker compose ps
```

停掉（队列数据还在卷里）：

```bash
docker compose stop
```

再启动：

```bash
docker compose start
```

连镜像一起停掉并删容器，但保留数据卷：

```bash
docker compose down
```

不要加 `-v`。`-v` 会删掉名为 `xuti-data` 的数据卷，队列和已保存的凭据会一起没掉。

### 不用 Compose 时

仍建议把端口绑在本机，和 `docker-compose.yml` 一样：

```bash
docker build -t xuti .
docker run -d --name xuti \
  -p 127.0.0.1:3847:3847 \
  -e CREDENTIALS_ENCRYPTION_KEY='换成你的长随机字符串' \
  -e X_API_MODE=mock \
  -e XUTIE_AUTOMATION_SUPERVISOR=off \
  -e HOST=0.0.0.0 \
  -e PORT=3847 \
  -e DATABASE_PATH=/data/xqueue.sqlite \
  -v xuti-data:/data \
  xuti
```

## 4. 不用 Docker，直接用 Node

在同一个文件夹里：

```bash
cp .env.example .env.local
npm install
npm run dev
```

`.env.local` 里同样改掉 `CREDENTIALS_ENCRYPTION_KEY`，并保持 `X_API_MODE=mock`。

浏览器还是打开 http://127.0.0.1:3847 。这个窗口要一直开着。关掉终端，调度就停了。

要把它留在后台时，先构建再启动，并用你自己的进程管理器保住这一个进程：

```bash
npm ci
npm run build
npm start
```

数据库在 `./data/xqueue.sqlite`。第一次启动会自己创建。新建的队列一开始是暂停的。

## 5. 第一次打开会看到什么

界面默认简体中文。侧栏底部可以点 **EN** 换成英文。

左边（窄屏在底部）有四页：

- **队列**：还没发出的和已经处理过的帖子
- **导入**：把文字放进队列
- **自动化**：关注和取关。默认关闭。第一次不要去开它
- **设置**：填写 X 的四项凭据

上面还有 **账号1** 和 **账号2**。这是两个分开的槽，各有各的凭据和队列。选中哪个，后面的页面就管哪个。新库里两个槽都是暂停的，按钮上会看到「暂停」。

侧栏会写「认证模式：模拟。这个进程不会请求 X。」以及「关注自动化：关闭。」

## 6. 先用模拟模式看一遍

还在 `mock` 时就可以操作，不会向 X 发帖。

1. 打开 **设置**，确认当前是账号1。
2. 四格随便填能看懂的测试文字。不要把 API Key 填成 `invalid`，模拟会把它当成认证失败。不要填 Bearer Token。
3. 点 **保存并测试**。成功时出现「已连上 @mock_……」。这是本机根据你填的内容编出来的名字，不是你的 X 账号，也不能证明密钥在 X 上有效。输入框会清空，密钥不会再显示。
4. 打开 **导入**。可以点 **填入示例**，或自己贴几行字。一行一条；空行可以分段；单独一行写 `---` 也是分隔。也可以上传 `.txt` 或 `.csv`。
5. 看预览。超过 25000 的不会入队。超过 280 的会标成「长文」。一次最多入队 50 条。
6. **开始时间**用你这台电脑的本地时间。点 **加入队列**。
7. 回到 **队列**。可以看到间隔（分钟，默认 15）和随机延迟（秒，默认最少 60、最多 120）。相邻两条的间隔是「间隔 + 这一段随机秒数」，不会短于间隔。改完要点 **保存节奏**。时间按这台电脑的本地时区显示。
8. 点 **继续发送** 之前，队列是暂停的，到点也不会发。模拟模式下点了继续，到点的文字只在本机被标成已发送，不会出现在 X 上。
9. **暂停全部** 可以再停下来。失败项用 **重试失败项**。还没发的可以改字、删除、上移下移。

想看失败时长什么样，可以在模拟模式的正文里加上这些标记：`[[duplicate]]`、`[[rate-limit]]`、`[[credits]]`、`[[auth]]`、`[[forbidden]]`、`[[fail]]`。它们只对模拟有效。

调度大约每 5 秒看一次两个账号槽。进程没在运行时，什么都不会发。进程恢复并且队列没有暂停之后，已经过点的帖子里最早的一条可以马上轮到，多出来的会按间隔重新排开，不会在同一轮里全部发出。

## 7. 什么时候才改成真实发帖

先确认你愿意用自己的 X 账号，并且接受 X 可能收费、限流或限制自动化。下面的价钱来自仓库 README 里引用的 2026 年公开资料，**以你自己的开发者控制台和账单为准**，这里不另写新价格。

仓库里写明的情况是：

- 发帖要用 OAuth 1.0a 的用户令牌，不能用应用级 Bearer Token。
- 新开发者一般没有旧的免费额度，默认按量计费。README 里提到：不含链接的发帖大约 0.015 美元一则，带链接的大约 0.20 美元一则；发帖前读取最近帖子也会扣读取费用。旧的包月 Basic / Pro 只留给已经在订的人。
- 公开资料里的频率上限会随套餐变。序帖默认大约 15 分钟一条，是为了不要连发。
- 令牌权限要先改成 Read and Write，再生成 Access Token。后改权限时，旧令牌经常仍是只读，发帖会 403。
- 控制台要填回调地址和网站。序帖不用跳转登录，可以先填 `http://127.0.0.1:3847`。
- 四项对照：API Key、API Key Secret、Access Token、Access Token Secret。

真实发送的顺序：

1. 队列保持暂停。侧栏应仍是「队列已暂停」。
2. 把 `X_API_MODE` 改成 `live`，然后重启这一个进程（`docker compose up -d` 或重新 `npm start`）。只改文件、不重启，运行中的进程不会变成 live。
3. 在 **设置** 里填入四项并保存。当前版本里，真实模式下「保存并测试」和「重新测试已保存的凭据」**不会**去调用 `GET /2/users/me`。还没有存过身份时，测试会失败，代码是 `identity_reconfirm_blocked`，提示不能用付费读取重新确认身份。这不表示四项一定抄错了。
4. 只有你决定真的发帖时，才回 **队列** 点 **继续发送**。到点后，调度会用已保存的四项请求 X，可能包括读取你的账号和创建帖子，并按 X 的价格扣费。成功的条目会带一条打开 `https://x.com/...` 的链接。
5. 发完或不想发了，点 **暂停全部**。

401，或明确说权限不对的 403，会暂停整个队列。重复内容、过长或没有 Premium 的长文，通常只让这一条失败。429 会按 X 给的时间等待。402 大约再等 10 分钟。这两种等待都不会把那条标成失败。

## 8. 自动化页先不要开

**自动化**是关注和取关，不是发帖所必需的。四项开关在 `.env.example` 里默认都是 `off`。页面上会写「关注自动化：关闭。」

第一次使用不要改这些开关，也不要在自动化页点启动。打开之后，程序可能对真实账号执行关注或取关，同样可能产生 API 费用，并受 X 的规则约束。那一套规则写在 [account-automation.md](account-automation.md)，是程序自己的逻辑，不是这份新手教程的默认设置，也不要照着别人正在跑的数字去改。

## 9. 数据放在哪里，怎么备份，怎么更新

发帖队列和加密后的凭据在 SQLite 里。

- Docker Compose：卷名 `xuti-data`，容器里的路径是 `/data/xqueue.sqlite`。
- 本机 `npm start`：默认 `./data/xqueue.sqlite`。旁边如果有 `-wal` 和 `-shm`，它们也是数据库的一部分。

程序没有「一键备份」按钮。要一份一致的副本时，先停掉进程或容器，再把数据库文件和旁边的 `-wal`、`-shm` 一起复制走，然后再启动。不要在它还在写的时候只复制其中一个文件。

更新程序时，重新下载或 `git pull`，然后重新构建。沿用原来的数据卷或 `data` 目录，并且沿用原来的 `CREDENTIALS_ENCRYPTION_KEY`。换了密钥，旧凭据就解不开，队列会暂停，需要到设置里重新填写。

不要把 `.env`、数据库文件发给别人。

## 10. 常见情况

| 你看到的 | 可以先检查 |
| --- | --- |
| 浏览器打不开页面 | 进程或容器是否还在。地址是不是 `http://127.0.0.1:3847` |
| 下载完 ZIP 却没有窗口 | 正常。还没有构建和启动 |
| 关了终端就不再发帖 | `npm start` 跟终端一起结束。要一直发，就用 Docker 的后台容器，或自己的进程管理器 |
| 到点了却没发出 | 队列是否仍暂停；`X_API_MODE` 是否为 `mock`；进程是否在跑 |
| 模拟里的 @mock_ 名字 | 这不是 X 上的真账号 |
| 真实模式下测试失败，并提到不能重新确认身份 | 与当前代码一致。不是叫你去点更多测试。暂停着就不会发帖 |
| 403 | 令牌是否在改成可读写之后重新生成过 |
| 改了加密密钥后全部停住 | 用新密钥无法解开旧凭据。到设置重新填写，再继续发送 |
| 端口被占用 | 已经有一个序帖在 3847。不要为了同时跑两份去改公网暴露 |

## 11. 这份教程检查过什么

写的时候对照了仓库里的 `README`、`.env.example`、`Dockerfile`、`docker-compose.yml`、界面文案和发帖调度代码。没有启动你的线上程序，没有填写真实凭据，也没有发帖或关注。

因此：页面上的按钮名称和默认数字来自源码；「在你电脑上执行 Docker 之后浏览器一定能打开」这一步，没有在写教程时实际跑过一遍安装。
